# sun-home 文件树统一开发方案（1.6.15）

> 状态：已完成（P0–P5，2026-10-31）
> 目标版本：1.6.15
> 编写日期：2026-10-31
> 适用环境：Obsidian 1.14.4，Windows，当前测试 vault
> 版本约束：1.6.14 已打 `1.6.14` / `v1.6.14` 标签，本次不回头修改已发布标签

## 1. 目标

把原生文件浏览器（Files）和单库树做成**同一个树内核的两个作用域实例**：

- 原生树：`scope = /`，显示整个 vault / 全部知识库。
- 单库树：`scope = 当前知识库路径`，只显示和操作这一个知识库。

除作用域外，两棵树在以下方面必须一致：

- 外观：行结构、行高、2px 行距、缩进、折叠箭头、选中态、当前文件态、置顶/隐藏标记、拖拽源样式、放置线、文件夹移入高亮、空态、滚动条。
- 操作：单击/Ctrl/中键打开、Alt+单击多选、Shift 范围选择、右键菜单、键盘导航、行内重命名、行内新建、拖拽排序、移入/移出文件夹、置顶/隐藏、排序方式、折叠/展开、自动定位、拖拽自动滚动、拖拽悬停展开、拖拽后保持视口。
- 数据：同一份 `OrderManager` / `order.items`，不做第二套顺序或置顶/隐藏状态。
- 性能：大知识库下只渲染视口附近的行；拖拽落点 O(1)；排序后不整棵树重建。

### 1.1 允许存在的差异

以下差异由作用域和视图边界决定，不视为“没有统一”：

1. 单库树没有跨知识库拖拽、跨知识库“移动到…”和跨知识库多选。
2. 单库树只有当前知识库的根，不渲染 vault 根，也没有“返回全部知识库”之外的额外根行。
3. 单库树保留“返回全部知识库 / 当前库名”的作用域外壳；树主体从库根的子项开始，和原生树从 vault 根的子项开始一致。
4. 折叠状态、自动定位开关、滚动位置属于视图状态，两棵树各自保存；行为规则相同，不强绑另一棵树。
5. 自动定位当前文件时，如果文件不在当前单库作用域内，单库树不做跨库跳转。

### 1.2 已确认的产品决定

| 决定 | 结论 |
| --- | --- |
| 单库树是否显示附件/非 md 文件 | **显示**。与原生树一致，不再只过滤文件夹和 `.md`。 |
| 单库树排序入口 | **改成和原生一样按文件夹排序**。删除“一次改整个库所有文件夹”的全局排序入口。 |
| 拖拽源行紫色 | **保留原生样式**。不新增单库树专属覆盖，避免再次出现“单库树特殊”。 |

### 1.3 由本方案确定的默认行为

- 单库树不把库名标题作为拖拽落点；拖到树内空白区等价于拖到当前库根，和原生拖到根目录空白区一致。
- 单库树的文件夹移入操作落到该文件夹末尾，不插到最前面。
- 单库树的“移动到…”只允许当前库内的目标文件夹；跨库移动不提供。
- 单库树使用原生 `.is-being-dragged` / `.is-selected` / `.is-active` 类名，不新增专属颜色。
- 核心右键菜单优先复用原生菜单生成逻辑；不可用时按原生菜单分组复刻，不继续维护现有简化菜单。

## 2. 原生基准（Obsidian 1.14.4 实测）

本节作为实现和验收的硬基准。以下数字来自当前测试 vault 的实测 DOM，不是估算：

| 项目 | 原生实测 |
| --- | --- |
| 行高 | `24.9px` |
| 行间距 | `margin-bottom: 2px` |
| 根容器内边距 | `padding: 4px 12px 24px` |
| 缩进 | 行内 `padding-inline-start = 24px + 17px × 深度` |
| 行宽 | 所有层级同宽，缩进靠行内 padding，不靠子容器宽度 |
| 行距/空白 | 2px 缝隙、右侧留白、容器上下 padding 都参与“方向感知 + 最近行”解析 |
| 虚拟列表 | 每个子级容器带 `0.1px` 占位条；顶部只保留视口附近的行（10k 实测约 40 行）；直接跳到底部时会保留大量行（10k 实测约 9984 行），不能把“任何位置都只渲染视口”当成原生承诺 |
| 文件夹落点 | 上 30% = before，下 30% = after，中间 40% = 移入 |
| 文件落点 | 上 50% = before，下 50% = after |
| 选中态 | `.is-selected`；当前打开文件是 `.is-active` |
| 多选 | Alt+单击切换选中；Shift+单击范围选中 |
| Ctrl/Cmd+单击 | 在新标签页打开，不是多选 |
| 右键菜单 | 原生菜单包含打开、复制/移动、路径/系统、置顶/隐藏、重命名、删除等分组 |

单库树要复刻的是以上契约，而不是只把 `25/50/25` 改成 `30/40/30`。

## 3. 现状与差距

### 3.1 现有实现

- 原生树拖拽：[src/core/dnd-engine.ts](../src/core/dnd-engine.ts)，document 级监听，操作原生 DOM。
- 单库树：[src/view-tree.ts](../src/view-tree.ts)，独立事件委托拖拽、递归全量渲染、库名标题落点、简化右键菜单。
- 排序数据：[src/core/order-manager.ts](../src/core/order-manager.ts)，两棵树已经共用同一份 `order.items`，这是统一的基础。
- 排序特性装配：[src/core/sort-feature.ts](../src/core/sort-feature.ts)。
- 拖拽/隐藏/图钉样式：[styles.css](../styles.css)。

| 能力 | 原生树 | 当前单库树 | 统一后 |

| 作用域根 | vault 根无行 | 库名标题作为落点 | 不渲染根行；树内空白映射库根 |
| 移入文件夹 | 落到末尾 | 落到最前 | 落到末尾 |
| 非自定义排序下拖拽 | 自动固化当前显示顺序并切 custom | 部分场景不完整 | 同一套固化逻辑 |

### 3.3 为什么不能继续打补丁

单库树现在是一个约 1000 行的独立实现，同时包含渲染、点击、拖拽、菜单、排序、折叠和自动定位。继续在 `view-tree.ts` 里补 `resolveDropSide`、`handleDrop`、`markDropTarget`，会持续产生两套规则：

- 一处改了落点比例，另一处没改；
- 一处修了 pinned/多选，另一处没有；
- 一处用全量 DOM，另一处用虚拟列表；
- 一处菜单是原生的，另一处是自定义的。

统一必须把“树的能力”从“视图的外壳”里拆出来，而不是继续增加条件分支。

## 4. 目标架构

```text
OrderManager / settings（唯一顺序数据源）
        │
        ├── 原生文件浏览器 DOM ── NativeTreeSurface ─┐
        │                                             ├── TreeDndController（共用规则）
        └── TreeModel ── KbTreeRenderer ── KbTreeSurface ┘
                              │
                    TreeInteractions / TreeMenu
```

### 4.1 分层职责

| 层 | 职责 |
| --- | --- |
| `TreeModel` | 单库树可见行模型：作用域、排序、折叠、置顶/隐藏/当前文件、附件显示、缩进层级 |
| `NativeTreeSurface` | 读取原生 DOM/fileItems/tree.selectedDoms，提供原生行几何、选中、展开、滚动、提交移动 |
| `KbTreeSurface` | 读取单库树模型和选中集合，提供模型行几何、展开、滚动、提交移动 |
| `TreeDndController` | 两棵树共用的拖拽规则：命中、落点、指示、排序模式、置顶、多选、自动滚动、展开、视口恢复 |
| `KbTreeRenderer` | 单库树专用渲染：原生 DOM 契约、虚拟窗口、增量更新、空态 |
| `TreeInteractions` | 单击/打开/多选/键盘/行内重命名/行内新建 |
| `TreeMenu` | 右键菜单：优先原生生成，作用域过滤，插件项注入 |

### 4.2 数据流

1. 文件系统或设置变化 → `OrderManager` / settings 更新。
2. 单库树重新计算 `TreeModel`（只重算受影响文件夹和可见窗口）。
3. `KbTreeRenderer` 局部更新 DOM；原生树由 Obsidian 自己重排。
4. 用户拖拽 → `TreeDndController` 判定落点 → 对应 Surface 提交 `OrderManager.move` + `fileManager.renameFile`。
5. 提交后两棵树都从同一份 `order.items` 读取，不产生第二份顺序。

## 5. 详细设计

### 5.1 TreeModel

输入：

- `rootPath`：原生为 `/`，单库为当前知识库路径。
- `orderManager`：唯一排序器。
- `collapsedPaths`：当前视图的折叠集合。
- 隐藏规则、显示隐藏开关、当前活动文件。

输出：

```ts
interface TreeRow {
  file: TAbstractFile;
  path: string;
  name: string;          // 文件夹名 / .md 的 basename / 非 md 的完整文件名
  kind: "folder" | "file";
  depth: number;         // 库根子项为 0
  parentPath: string;
  pinned: boolean;
  hidden: boolean;
  active: boolean;
  collapsed: boolean;
}
```

规则：

- 排序只调用 `OrderManager.getSortedItems`，不在渲染层自写比较器。
- 文件夹与文件都参与排序；非自定义排序遵循 `OrderManager` 的“文件夹优先”规则。
- `.md` 显示 basename；附件/非 md 也显示 basename，并额外挂原生 `.nav-file-tag` 显示扩展名（如实测原生 `附件.png` 行文本为「附件」+ 标签「png」）。
- 隐藏项仍生成模型行并加 `.kb-hidden`，是否可见由 `body.kb-show-hidden` 和 CSS 决定，和原生一致。
- 只对当前作用域内的文件夹递归；作用域外的路径绝不进入模型。
- 模型缓存按 `rootPath + 折叠集合 + settings 版本 + vault 结构版本` 失效，避免每次点击全量重算。

### 5.2 KbTreeRenderer

DOM 契约必须和原生一致：

- 行：`.tree-item.nav-folder` 或 `.tree-item.nav-file`。
- 行自身：`.tree-item-self.nav-folder-title` / `.tree-item-self.nav-file-title.tappable.is-clickable`。
- 文本：`.tree-item-inner.nav-folder-title-content` / `.nav-file-title-content`。
- 折叠：`.tree-item-icon.collapse-icon`，折叠时同时给 item 和 icon 加 `is-collapsed`。
- 行内缩进：`margin-inline-start: 0 !important; padding-inline-start: 24 + 17 × depth px !important;`，行宽和原生一致。
- 行距：行自身 `margin-bottom: 2px`，不额外加容器间距。
- 状态：`is-active`、`is-selected`、`is-being-dragged`、`kb-hidden`、置顶 `.kb-indicator/.kb-pin-indicator`。
- 拖拽：行设置 `draggable="true"`，`data-path` 指向 vault 绝对路径。

虚拟化：

- 以固定行高为基础建立“可见行 → 视口窗口”的映射；行高从当前主题实测，监听字体/主题变化后重新测量。
- 渲染视口窗口 + 上下 overscan；窗口外只保留上下占位条，不创建行 DOM。
- 保留原生可见分支的嵌套骨架（`.nav-folder-children`）和 `0.1px` 占位条，确保依赖原生嵌套选择器的主题仍生效。
- 目标：单库 10,000 个条目时，顶部和常规滚动只保留视口窗口；底部行为以原生同场景为不劣化基线，不把“底部也只保留视口”当硬指标（原生 1.14.4 跳到底部时本身会保留大量行）。

增量更新：

- 当前文件切换：只切 `.is-active`，不重建。
- 置顶/隐藏变化：只更新受影响行和指示器。
- 拖拽排序/跨文件夹移动：只更新受影响文件夹的模型与窗口，保留滚动锚点。
- 只有切换知识库、根路径失效、全量设置重置时才允许整树重建。

空态：

- 当前库为空时，`.nav-files-container` 本身是根落点；空态文案保留在树主体内，拖动条目到空白区可移回库根。
- 库不存在时显示“知识库不存在”，不保留拖拽监听。

### 5.3 TreeDndController

#### 5.3.1 Surface 接口

```ts
interface TreeDndSurface {
  readonly scrollEl: HTMLElement;
  readonly scopeRootPath: string;

  resolveRow(target: EventTarget | null): RowHit | null;
  rowGeometry(path: string): DOMRect | null;
  visibleRows(): RowGeometry[];

  selectedPaths(): string[];
  isPinned(path: string): boolean;
  isCollapsed(path: string): boolean;
  expand(path: string): void;

  orderedChildPaths(folderPath: string): string[];
  beginScrollRestore(): void;
  commitDrop(drop: DropCommand): Promise<void>;
  isInScope(path: string): boolean;
}
```

- `NativeTreeSurface`：从原生 `.nav-files-container`、`.tree-item`、`tree.selectedDoms`、`fileItems`、`getSortedFolderItems` 读取；作用域为 `/`。
- `KbTreeSurface`：从 `TreeModel`、单库选中集合、折叠集合、虚拟滚动容器读取；作用域为当前库。
- 共用规则只写一次，两个 Surface 不再各写一套 `resolveDropSide` / `handleDrop`。

#### 5.3.2 落点规则（两棵树完全一致）

| 命中位置 | 结果 |
| --- | --- |
| 文件夹行上 30% | 排到该文件夹之前 |
| 文件夹行下 30% | 排到该文件夹之后 |
| 文件夹行中间 40% | 移入该文件夹 |
| 文件行上 50% | 排到该文件之前 |
| 文件行下 50% | 排到该文件之后 |
| 2px 行距 | 按指针 y 找最近行；平局优先“下一行之前” |
| 树顶/树底/右侧留白/容器 padding | 同“最近行 + 方向” |
| 容器没有任何行 | 移入当前作用域根/当前文件夹 |
| 作用域外 | 没有落点，不移动 |

#### 5.3.3 排序与移动语义

- 落在条目上/下沿 = 手动排序意图：目标文件夹如果还不是 `custom`，先按**当前显示顺序**把 `customOrder` 灌满，再切 `custom`，然后写入落点。
- 落在文件夹中间 = 移入：不改变排序模式；目标位置是该文件夹当前显示顺序的末尾，排除被拖动/被选中的条目。
- 跨文件夹移动：先 `fileManager.renameFile`，再 `OrderManager.move`；vault rename 事件和调用方的重复进入必须保持幂等（现有 `OrderManager.move` 的 `alreadyTransferred` 逻辑保留）。
- 置顶条目：不能跨文件夹移动；置顶/非置顶混选不能整组移动；同一文件夹内按落点重排允许。
- 多选：若拖拽行属于选中集合，整组移动；第一项使用指针落点侧，后续项依次插到前一项之后；顺序与当前可见顺序一致。
- 拖动文件夹不能落到自身或自身子孙。
- 单库树作用域外一律拒绝；原生树作用域为整个 vault，可跨知识库。

#### 5.3.4 拖拽辅助行为

- 边缘自动滚动：距离容器上下边缘 60px 内启动，速度 20，按距离平方衰减；滚动后重新解析落点。
- 悬停折叠文件夹 1 秒展开；展开后重新解析落点，不重建正在拖拽的源节点。
- 拖拽指示只操作上一次的两个目标元素，不做全文档 `querySelectorAll`。
- 手动排序完成前记录滚动位置；排序后用 rAF + 80ms 兜底恢复，覆盖“自动定位当前文件”抢滚动。
- 拖拽样式只使用原生 `.is-being-dragged`；单库树不额外给库名标题加拖拽高亮。

### 5.4 TreeInteractions

#### 5.4.1 点击与选中

- 单击文件：打开；单击文件夹：展开/折叠，行为与原生一致。
- 普通单击与 Ctrl/Cmd+单击只移动锚点，不产生 `.is-selected`；原生同样只在 Alt/Shift 多选时出现选中态。
- Ctrl/Cmd+单击：在新标签页打开。
- 中键：在新标签页打开。
- Alt+单击：切换选中，不打开。
- Shift+单击：以当前锚点做范围选中，不打开。
- 选中类 `.is-selected`，当前打开文件类 `.is-active`，两者独立。
- 单击已打开的活动文件不重复打开。
- 拖拽未选中的行时只移动该行；拖拽已选中的行时移动整个选中集合。

#### 5.4.2 键盘

对齐原生文件浏览器的键盘操作，至少包含：

- 上下方向键移动焦点/选中；
- 左右方向键折叠/展开文件夹，或在层级间移动焦点；
- Enter 打开；
- F2 行内重命名；
- Delete 删除选中项；
- Home/End 到首尾；
- Esc 取消重命名/关闭菜单，不误触发移动。

P0 阶段用原生行为采样确认每个按键的实际语义，再按采样结果实现，不凭印象补键位。

#### 5.4.3 行内重命名与新建

- 重命名在树行内完成，使用原生 `.is-being-renamed` 结构和输入框，不用弹窗。
- Enter 提交、Esc 取消、失焦提交；重名/非法名显示原生风格的错误态。
- 新建文件夹：在目标文件夹内建「未命名」并立即进入行内命名（与原生一致）。
- 新建笔记：在活动笔记所在文件夹内建「未命名」并直接打开（原生 `afterCreate` 对文件就是打开，不对文件行做行内重命名）；不再弹自定义模态框。
- 工具条的新建落点跟原生 `getNewFileParent` 一致：活动笔记在当前库内时用其父文件夹，否则用库根。
- 输入法组合输入期间不提交、不重排、不重建 DOM。
- 新建/重命名完成后滚动到新行并保持焦点。

#### 5.4.4 自动定位

- 当前文件切换时，单库树展开其所有父级并滚动到可见位置，和原生一致。
- 手动拖拽排序后保持用户当前视口，不因自动定位跳回活动文件。
- 自动定位开关按视图保存；关闭后只更新 `.is-active`，不展开、不滚动。
- 活动文件不在当前库作用域内时，单库树不做跨库定位。

### 5.5 TreeMenu

目标：单库树右键菜单不再是一份简化菜单，而是与原生同一套分组和顺序。

优先级：

1. **核心项按原生复刻**：原生 `onFileContextMenu` 会触发 `file-menu`，而 Obsidian 核心的 `file-menu` 监听器会再注入一整套标准项（复制路径/使用默认应用打开/移动文件等），其中「移动文件」列出的是整个 vault。单库树直接触发会让核心项重复且绕过作用域过滤，因此改为按原生标题、图标、section 顺序复刻核心项，不触发 `file-menu`。
2. **本插件项**：置顶/隐藏/排序继续通过 `SortFeature.addFileMenuItems` 直接注入，和原生树共用同一套逻辑；菜单动作后立即刷新单库树。
3. **多选菜单**：按原生 section 顺序复刻（创建新文件夹 / 将 N 个文件移动到… / 删除）。`files-menu` 同样会让核心再注入跨库「移动到…」，因此不触发。
4. **代价**：第三方插件通过 `file-menu` / `files-menu` 注入的单库树菜单项不会出现；原生树不受影响。跨库「移动到…」在单库树仍然不提供。

单库树作用域过滤：

- “移动到…”只列当前库内的文件夹，不列其他知识库。
- 跨库拖拽、跨库多选、跨库移动不提供。
- “在系统资源管理器中显示”“复制路径”“重命名”“删除”等库内操作保留。
- 文件夹右键保留“排序方式”子菜单；根目录空白右键对当前库根排序。
- 删除确认、重命名冲突、文件已存在等提示沿用 Obsidian 原生行为；不再额外套一层自定义确认框，除非原生行为本身需要。

排序入口调整：

- 删除单库树工具条的“全库排序”按钮和 `applySortOrder` 递归逻辑。
- 每个文件夹的排序只作用于该文件夹；根文件夹通过树内空白区右键设置。
- 排序方式仍写入 `OrderManager` 的 `FolderSettings`，和原生树共用。

### 5.6 作用域外壳

单库树保留：

- “← 全部知识库”返回入口；
- 当前库名；
- 新建笔记、新建文件夹、自动定位、折叠全部/展开全部、刷新等工具按钮（按钮使用原生 `clickable-icon nav-action-button` 类）。

单库树移除：

- 库名标题作为拖拽落点的 `data-path` / `data-kb-drop-folder`；
- 库名标题的拖拽高亮 CSS；
- 工具条的全库排序入口。

树主体的第一个可滚动元素仍然是 `.nav-files-container`；根目录在视觉上不占一行，和原生 vault 根一致。

### 5.7 CSS 调整

- 保留并复用两棵树共用的放置线、文件夹移入高亮、图钉、隐藏态样式。
- 删除 `.kb-tree-title[data-kb-drop-folder]` 及单库树根标题拖拽高亮。
- 单库树行的缩进改为行内 `padding-inline-start`，不再依赖 `.nav-folder-children` 的累计宽度。
- 单库树容器补齐虚拟占位条样式；空库/空文件夹根落点高亮与原生一致。
- `body.kb-dragging` 下的自动滚动禁用规则同时覆盖原生树和单库树，两棵树都使用自建边缘滚动。
- 不新增 `.tree-item-self.is-being-dragged` 的颜色覆盖；紫色保持 Obsidian 原生样式。

### 5.8 性能设计

1. **渲染**：顶部和常规滚动使用虚拟窗口 + overscan；不为追求“底部 ≤200 行”去超出原生行为，底部以“不劣于原生同场景”为验收线。
2. **排序**：只对发生变化的文件夹重排；`OrderManager` 已用 `Map` 预建索引，保持不改回 O(n²logn)。
3. **命中**：`elementFromPoint` + 行数据；空白区只在可见窗口内找最近行。
4. **更新**：活动文件、置顶、隐藏只切类；移动只更新受影响分支。
5. **事件**：拖拽期间不做全量 DOM 查询；不因一次落点清理扫描全树。
6. **视口**：排序/移动后按路径或 `scrollTop` 恢复锚点；自动定位只在需要时滚动。

验收目标（以原生同场景为基线，P0 先记录原始数字）：

- 单库树 10,000 条：顶部与常规滚动 DOM 行数不超过“视口行数 + 2 × overscan”，不随总数线性增长；
- 底部行数不高于原生同场景（P0 实测原生 10k 跳到底部约 9984 行，不能把底部 ≤200 当原生基线）；
- 初始可交互、滚动、拖拽排序与原生同场景处于同一数量级（P0 实测原生展开 1.47s，单库打开 2.78s，仍在 2× 内）；
- 拖拽期间不出现超过 50ms 的长任务；
- 排序/置顶/隐藏不触发全树重建；
- 排序后视口保持，不跳回活动文件。

### 5.9 兼容性

- 以 Obsidian 1.14.4 为验收版本；私有 API（`fileItems`、`tree.selectedDoms`、`onFileContextMenu`、`getSortedFolderItems`、`infinityScroll`）全部做能力检测。
- 原生 API 缺失时降级：菜单退回分组复刻，展开退回 DOM 点击，排序退回 `OrderManager` 顺序。
- 主题：保留原生嵌套容器契约和行内缩进；以默认主题和用户当前主题实机截图对比。
- 第三方插件：通过标准 `file-menu` 事件注入的菜单项应正常出现；硬编码原生文件树 DOM 的插件不在保证范围内。

## 9. 风险与应对

| 风险 | 应对 |
| --- | --- |
| 原生私有 API 变动 | 全部能力检测；菜单/展开/排序有降级路径；以 1.14.4 为验收版本并保留回归 |
| 多选菜单桥接依赖原生 `selectedDoms` | 不伪造原生选择；多选走独立菜单生成，P0 先验证 |
| 虚拟化与主题嵌套 CSS 冲突 | 保留可见分支的 `.nav-folder-children` 骨架和原生占位条；默认主题 + 用户主题双验收 |
| 行高随字体/主题变化 | 运行时测量行高并监听变化，不把 `24.9` 写死到虚拟计算 |
| 行内重命名输入法 | 组合输入期间不提交/不重排；用真实中文输入样本验收 |
| vault rename 事件与调用方重复进入 | 保留 `OrderManager.move` 的幂等处理，补事件顺序回归 |
| 自动定位抢滚动 | 排序前记录锚点，rAF + 80ms 恢复；只在自动定位开启时滚动 |
| 单库作用域误操作库外文件 | Surface 的 `isInScope` 在落点/菜单/移动三层都校验 |
| 菜单或展开逻辑在原生面板重建后失效 | document 级控制器 + Surface 每次按当前容器解析，不缓存失效 DOM |

## 10. 明确不做

- 不克隆、嵌入或伪装原生 `FileExplorerView` 来当单库树。
- 不通过 CSS 隐藏原生树的其它根目录来实现“单库模式”。
- 不做单库树跨知识库拖拽、跨库“移动到…”或跨库多选。
- 不统一卡片墙 `KbHomeView`。
- 不改变原生树已经确认的落点语义：30/40/30、最近行 + 方向、移入末尾、拖条目切自定义排序。
- 不共享两棵树的折叠/自动定位/滚动状态；只统一规则。
- 不新增单库树专属紫色拖拽样式；保留 Obsidian 原生。
- 不为第三方插件硬编码原生文件树 DOM 的行为做保证。
- 不在本次改动中顺带增加与统一无关的新功能。
